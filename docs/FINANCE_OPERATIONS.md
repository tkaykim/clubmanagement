# 원샷크루 재무 운영 안내

## 화면과 권한

`/finance`는 대표·재무담당자와 프로젝트별 재무 담당자의 업무 화면이다.
`/my-settlements`는 로그인한 사람이 본인의 확정 수당과 지급 내역을 확인하는 화면이다.
일반 운영진이나 owner 등급만으로 전체 예산을 볼 수는 없다.
전역 권한은 `finance_access_grants`, 프로젝트 범위는 `finance_project_managers`가 결정한다.
일정 관리용 `project_managers`와 재무 담당자를 혼동하지 않는다.

대표·재무담당자는 예산과 담당자를 관리하고 배분안을 확정하며 수금·지급 증빙을 등록한다.
프로젝트 담당자는 담당 프로젝트의 전체 수당을 조회하고 배분안을 작성·제출한다.
담당자가 아닌 사람에게는 총예산, 다른 사람의 수당, 합계, 증빙 원문을 제공하지 않는다.
담당자 해제 이후에도 본인의 확정 정산은 남는다.

재무 목록·요약 합계에서는 무료(`projects.pay_type = 'free'`) 프로젝트를 제외한다.
금액이 0원이거나 미확정이라는 이유만으로 유료·협의 중 프로젝트를 숨기지는 않는다.
무료 프로젝트의 기존 정산·증빙은 삭제하지 않으며 본인의 확정 정산과 권한 있는 직접 상세 조회는 유지한다.
담당자 지정과 수당 명단 추가는 이름을 검색한 뒤 드롭다운에서 선택한다.

## 금액 입력

고객 계약금액과 내부 집행 한도를 구분한다.
공급가액·부가세·청구합계 중 확인된 값만 입력하며, 미확인을 0원으로 바꾸지 않는다.
부가세 포함 총액만 합의했다면 총액과 금액 기준을 기록하고 세액을 임의로 확정하지 않는다.
프로젝트 공용 `fee`, 설명, 일정, 공지에는 예산이나 수당을 입력하지 않는다.

배분안에는 참여자, 지급 사유, 세전 수당, 세무 유형, 예정일과 근거를 기록한다.
메일에 적힌 금액이 세전인지 세후인지 불명확하면 요청 원문을 남기고 수당·세무 유형을 미확정으로 보존한다.
본인 정산에는 확정된 내역만 공개한다.
3.3% 계산 결과는 지급 예정액이며 실제로 받은 금액이 아니다.
계산 정책 버전과 확정 시점의 세액을 보존하며 과거 지급액을 새 정책으로 재계산하지 않는다.

## 수금과 지급

고객의 입금과 참여자에게 보낸 돈은 서로 다른 거래다.
통장 거래 ID, 출처, 날짜, 금액, 증빙을 대조한 뒤 실제 거래를 등록한다.
부분 입금·부분 지급은 각각 기록하며 같은 거래를 반복 등록하지 않는다.
다른 프로젝트의 동명이인 거래나 비슷한 금액을 이번 행사에 임의로 연결하지 않는다.
이 화면의 증빙 등록은 장부 기록이며 은행 이체를 실행하지 않는다.
지급과 계산서 발행은 담당 재무 절차 및 사람 승인에 따라 별도로 실행한다.

계산서·메일·ERP·Clobe의 원천 식별자는 비공개 재무 근거로 연결한다.
원천 시스템의 거래를 앱에 기록해도 원천 원장을 다시 생성하거나 이중 지급하지 않는다.
발행 요청 메일만 확인했다면 발행 완료로 처리하지 않는다.
입금 요청이나 지급 승인만으로 수금·실지급 완료를 기록하지 않는다.

## 안전한 확인과 인계

메일·계약서 원문, 실계정 정보, 실제 예산 데이터는 공개 저장소에 커밋하지 않는다.
테스트에는 분리한 계정과 비공개 합성 프로젝트를 사용한다.
검증이 끝난 합성 재무 프로젝트는 `finance_set_project_archive`로 보관해 기본 목록과 합계에서 제외한다.
보관은 삭제가 아니며, 권한 있는 상세 조회와 감사 이력은 남긴다.
예산·배분·권한 변경과 다운로드는 감사 이력으로 확인한다.
합성 E2E 프로젝트는 삭제하지 않고 재무 담당자가 감사 사유와 함께 보관 처리한다.
보관 처리된 프로젝트는 기본 재무 목록과 합계에서 제외되지만 권한 있는 상세·감사 조회로 복원할 수 있다.
권한 회수는 이후 접근을 차단하지만 이미 내려받은 파일은 회수할 수 없다.
재무 계정은 공연 멤버의 공개 프로필이나 활동 승인을 받을 필요가 없다.
최초 비밀번호는 로그인 화면의 비밀번호 설정·재설정 메뉴에서 본인 메일함 인증으로 설정한다.
